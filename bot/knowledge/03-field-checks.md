# Field checks

By Major · Unofficial

Derived from [Field traps](../../skills/whop-quick-scaler-launcher/references/field-traps.md). Reference date: 2026-09-29. Historical observations must stay qualified. These checks belong to the user or an authorized operator; the advisory bot never performs account operations.

## Match the symptom to the check

- Wrong business: compare ownership before and after any separately authorized operation. Reuse the existing draft; do not repair a mismatch by making duplicates. FT01.
- Lost sign-in: pause dependent work, preserve progress and have the owner restore secure authentication. A fresh read must work before resumption. FT02.
- Accidental production test: the CLI has no sandbox or dry-run mode. The separate API sandbox has limitations, including unsupported app and embedded-checkout scenarios. FT03.
- Unchanged public address: verify the returned route and rendered destination; an accepted option is not proof it took effect. FT04.
- Validation or replay error: inspect the schema. Retry an identical operation with its original supported idempotency key; changed requests need a new key after reconciling the old outcome. FT05.
- Missing image: distinguish file record, transferred bytes, processing, attachment and buyer rendering. Preserve unrelated gallery entries. FT06.
- Redirect loop: use checkout-specific destinations, a visible skip path and a terminal delivery page. Preserve the canonical checkout. FT07.
- Missing order bump: inspect current capabilities; an old tutorial does not establish a current checkbox or its permanent removal. FT08.
- Invisible discount: compare the display control with the actual payable amount. Never invent a reference price. FT09.
- Wrong PDF: check product-restricted access and download the correct edition as an authorized buyer distinct from the administrator. FT10.
- Reverted edit: close stale forms without saving; reconcile concurrent changes. FT11.
- Unexpected defaults: inspect affiliation, phone collection, member display, billing and access. A waitlist is not automatically card-free. FT12.
- False publication: verify exact content, visibility, checkout availability and Marketplace status separately. FT13.
- Accidental payment: stop passive QA before any pay, join or approve action. Saved payment methods increase risk. FT14.

## Evidence to retain

Record what was actually checked and by whom. Separate configured redirect, executed redirect, actual payment and correct buyer delivery. Keep unsupported stages unverified.
